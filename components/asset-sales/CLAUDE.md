## Asset Sales (single input path — single/bulk tab split removed)
- Route `app/(analysis)/asset-sales/page.tsx` renders `components/asset-sales/AssetSalesTab.tsx` directly (no `<Tabs>`/Panel wrapper — the single-vs-bulk tab distinction was merged away since both always shared the same `fetchAssetXlmProceeds` engine and render components)
- Selection is shared with Asset Lookup Distribution Sales through `selectSellerAccounts`: manual override first, all saved distributors for the exact code+issuer+network second, otherwise every proven retained-history receipt candidate. `inferDistribLite` follows successful claim operations (including issuer-created claimables), retains historical forwarding accounts for sale verification, and stores transaction/operation provenance. Funding is not proof of selling. Chronological attribution excludes future payments; partial attribution is explicit. More than 20 recipients, three relay hops, pruned proof, cycles or already-traced convergence require manual accounts; no silent top-five truncation.
- **Manual override**: when exactly 1 pair is parsed, an optional "Seller Accounts (override, optional)" textarea appears — paste specific addresses to skip auto-infer entirely (covers the old single-tab manual-entry case and the auto-infer-fails fallback). Hidden when 2+ assets are entered — always auto-infer per asset in that case
- Results render row-count-aware: 1 result renders wide (large asset code, full-width non-truncated `ShortAddress` rows) matching the old single-tab look; 2+ results render as compact summary rows (fixed-width columns) — same `rows.map` block, gated on `rows.length === 1`
- `app/(analysis)/bulk-asset-sales/page.tsx` is now a redirect to plain `/asset-sales` (old bookmarks/dashboard card still work)
- Issuer home-domain enrichment runs independently of sales; cancelled requests cannot update rows. Cancel retains completed results, labels active rows stopped and does not display a refresh warning. Restored unfinished checkpoints have a separate dismissible notice.
- Deep-links all land in the one textarea: `?bulkAssets=` prefills multiple lines; `?asset=`/`?code=`+`?issuer=` prefills one `CODE:ISSUER` line (`?account=` also prefills the override field); `?autorun=1` triggers `handleRun()` once the prefilled text lands. `SavedAnalysesPanel` re-run buttons run in-place (don't navigate here at all); Search History and Asset Lookup's "View full data in Asset Sales" push the `?asset=&issuer=&account=&autorun=1` params
- History hook is `useProceedsHistory.ts` (renamed from the old bulk-only `useBulkProceedsHistory.ts` — same storage key/shape, now the single merged recent-searches list). Presets (a separate save/apply/delete-by-id feature) were removed entirely — Saved Analyses' re-run button covers that use case
- Proceeds correlate each trade with its operation: own path fills are excluded and qualifying path endpoints counted once; other accounts' maker fills remain eligible. Unlinked/unverified trades are excluded with incomplete-coverage warnings. Gross sale output, target purchases, all-asset purchases, external/internal transfers and balances at scan are separate; the legacy estimated-on-hand field is never presented as actual cash or profit. Fee and opening-balance accounting is not a profit calculation.
- The evidence panel shows seller status, funding/claim proof, sale evidence IDs, requested period and coverage. Automatic selection uses an authenticated asset-specific distributor read when the group cache is pending; failure never falls back silently to inference. Manual overrides skip that read. Older snapshots keep their stored data and display unknown coverage/legacy accounting until re-run.
- Beneficiary credit destinations: optional network-aware enrichment fetches each external XLM transfer transaction once (four requests in flight), verifies successful hash-matched transaction metadata, and groups by exact network + recipient + memo type + memo value. Unknown metadata is excluded; verified no-memo destinations remain address-only. Text whitespace/case/Unicode/leading zeros and uint64 ID strings are preserved. No exchange or ownership inference. Group data and operation evidence are additive snapshot fields; re-run populates older records.
- Muxed recipients use their full M address in the exact grouping key while retaining the base G address for financial accounting/display. A muxed ID without its full address is unresolved, never collapsed into the base-only destination. Leading BOM text is retained exactly.
- Soroban conversions: successful invoke_host_function records contribute contract_sale/contract_purchase only when verified account transfer endpoints contain one debit asset and one different credit asset. Exact code+issuer matching applies; no endpoint netting, contract-to-contract XLM, or duplicate classic trade attribution. Missing/malformed, mixed or round-trip endpoints mark coverage incomplete. contractSaleCount is separate from classic DEX/path counts; complex contract native transfers remain unsupported and warned. Real GBVI fixture independently matches account effects (contract effects are not added again).
- Top 3 holders: `TopHolders.tsx` runs `lib/proceeds-investigator/top-holders.ts` on demand for a single parsed asset, scans every account trustline before ranking, and preserves exact code+issuer identity. Percent denominator is all scanned account balances plus verified claimable/pool/contract amounts; unknown metadata gives Unknown percentages. Full pagination and abort checks prevent partial rankings; asset/network changes remount and abort. Use as seller appends to the manual override without replacing prior addresses or running analysis. Holdings are clues, never proof of selling; account-only ranking and non-atomic scan time are explicit.

- Saved history loads only after a valid asset is entered and never gates Run Analysis. There is no background-loading banner; a comparison error offers Retry history without blocking sales. Completion uses the latest loaded history for comparison; unavailable/partial history skips comparison and duplicate suppression without replacing older entries.
- Asset Sales opts into 30-second Horizon request budgets covering fetch, response body and retries; pagination has no whole-scan deadline. Holder supply metadata has a 5-second budget and degrades to unknown percentages. Saved-distributor authentication plus reading has a cancellable 20-second budget. Other modules keep their existing request defaults.
- Late scan-state restoration is ignored once a new scan starts or Clear is pressed, so delayed initial reads cannot overwrite current rows or resurrect cleared rows.
- Detailed coverage, memo beneficiary groups, accounting explanations and seller proof are inside the collapsed Analysis details disclosure; incomplete history stays visible in its summary. Statistics and destination tables stay visible. Other modules retain their existing shared presentation.
- Retention alone does not imply missing account history: when every selected account's earliest retained payment is its successful creation within the retained ledger range, coverage is bounded to those observed account lifetimes and creation evidence is saved. Earlier incarnations and other sellers are not proven covered; accounting/pagination warnings still prevent complete status. Older snapshots are not rewritten.
- Top holders can be explicitly added as distributors to an existing group matching exact asset code+issuer+network; existing members keep their roles. Manual seller selection remains separate. Mainnet assets link to Lobstr with preserved code case. The result header shows weighted average gross XLM/token from the covered sales, not a current quote.
- Top Verified Buyers: `TopVerifiedBuyers.tsx` runs the isolated `top-buyers.ts` engine on demand for one exact asset, ranking by verified XLM spending with 7-day, 30-day and all-available-history windows. Both classic XLM-pair orientations are paginated/deduplicated; operation proofs are cached and checked by four workers. A path's payer is `from`, not its recipient; own path endpoints count once and intermediate XLM from non-XLM sources is excluded. Maker fills remain eligible. Amounts/ranking use integer stroops. The table exposes purchase proof and coverage limits; Stop retains clearly partial results and asset/network changes abort old work. It never changes seller selection, holders, saved analyses, or Run Analysis availability. OTC, other pairs and contract swaps are outside this ranking's scope. Browser live-capture replay is opt-in via `TRSY_BUYERS_REPLAY=/tmp` after collecting public GET responses; the checked-in real TRSY fixture is a bounded proof sample, not full market history.
